# 联机广场

广场只提供玩家主动公开的房间码，不采集、上报或展示人数。原生软件的 20 人限制包含在线和离线成员，是否能加入由原生软件判断。

## 交互

联机页在「最近房间 / 联机广场（测试）」之间切换。标签内的 ? 说明实验性质、房间码上传及原生加入规则；完整隐私说明见 [PRIVACY.md](../PRIVACY.md)。房内只有已确认的房主能发布；已有本机发布意愿或待确认操作时，即使官方连接中断、房主状态未知或房间面板清空，也保留撤下入口。发布、撤下均先确认，取消不请求服务器。列表只显示房间码和进入按钮；随机进入只使用当前有效缓存页，不自动连续尝试其他房间，不报告全局满员状态。

每页 20 条。手动刷新等待 30 秒；翻页不等待刷新冷却，但受独立请求限流。上次成功页、分页缓存和刷新截止时间持久化，重开面板不重置。读取失败保留上次成功列表，到期公告仍隐藏。排序按本次首次发布时间倒序，续期不提升排名。

## 发布生命周期

公告有效 15 分钟，每 5 分钟续期。发布意愿、待确认写操作及撤下状态保存在原生主窗口的 localStorage，按服务端地址隔离。重启后必须同时确认原生账号、房间及房主身份，不根据旧发布记录推断房主。原生状态未恢复或连接中断时不续期；明确离房、退出登录、账号切换或失去房主身份时撤下。

原生面板隐藏时不持续广播房间快照。同一原生连接内可保留已经确认的房间状态；通过只读观察原生 WebSocket 的既有发送识别连接，关闭、替换、网络离线时清除确认，不主动连接或发送帧。首次观察可能等待下一次原生发送/心跳。后台重启或断线后若面板隐藏，需打开联机页获取新快照才能恢复发布，不能用旧记录替代。

发布前查询自己的公告，取得 generation；发布和撤下带持久化的幂等 key。失败重试复用原 key，旧公告代次不能操作新公告。发布过程中离房或撤下，迟到成功响应会触发补偿撤下。撤下失败时停止续期，保存待撤下操作，后台重启后仍可继续。关闭脚本不清除恢复记录。

## 网络与身份

基址为 `https://api.i02zane.site/wuwa-tappo-plus/v1`。页面经 CDP Runtime.addBinding / bindingCalled 事件直接提交固定业务操作，Python 标准库发起异步 HTTPS；HTTP Future 完成后立即回调页面，再由状态事件推送到联机面板。操作请求与结果不通过一秒轮询搬运；正常守护循环只负责页面发现与重挂载，原生状态与续期仍按原有定时器检查。页面只提交 list/own/publish/withdraw/reset 固定业务操作；页面不能指定 URL、头、凭据、路径或任意正文。不读取或上传官方 Token，不新增官方 HTTP 请求或 Socket.IO 连接。加入房间仍填写原生输入框、点击真实加入按钮。

服务端匿名凭据由 Python 保管，当前 Windows 用户 DPAPI 加密后原子保存到数据目录的 plaza_auth.json。普通卸载保留，完整卸载清除；日志导出不收集。页面只保存官方账号标识用于本机恢复意愿，不上传该标识。身份失效或凭据无法读取时停止自动请求，由用户明确点击「重建广场身份」恢复；旧公告自然到期，不循环申请身份。

后台为凭据生成带用途前缀的不可逆本地标记 identity_epoch，供页面绑定恢复记录；该标记不是认证凭据，不发给服务器。重启后先核对标记，凭据因完整卸载或手动重建而变化时清除旧发布意愿和待确认写操作，必须再次确认发布，不能继承旧浏览器记录自动公开房间。

后端只确认公告归属，不保证发布者是真实官方房主。客户端房主判断不等于服务端认证，匿名限流也不能保证阻止伪造公告。

## 客户端接口约定

- POST /sessions，正文 {}，后台首次使用时创建匿名身份，完整凭据只返回后台。
- GET /rooms?page=0&refresh=1；手动刷新 refresh=1，翻页 refresh=0。
- GET /me/room：核对自己的有效公告，无公告时 item=null。
- PUT /me/room：仅 room_code 与 generation，Idempotency-Key 请求头。
- DELETE /me/room：If-Match 公告代次，Idempotency-Key 请求头。
- GET /healthz：独立只读健康检查，不代替原生联机连接状态。

列表返回 items/page/has_more/server_time/next_refresh_at；公告包含 id/room_code/published_at/updated_at/expires_at，自身公告另外返回 generation。凭据、人数和内部归属字段不进入页面快照。Python 对成功响应做类型与大小检查，未知字段不转发。根据 server_time 处理客户端时钟偏差。

429/503 使用 Retry-After，区分维护、发布关闭、冲突、凭据失效及一般连接错误；列表刷新冷却不阻挡撤下。请求有大小、并发和速率限制，HTTPS 不跟随重定向，单次 5 秒、响应最多 256 KiB。服务端独立限流，不能把客户端限制称为云端防刷。

## 开发与验证

npm ci 后运行 npm run build:plaza，生成被忽略的 plaza-client.bundle.js 和 plaza-config.json。默认构建地址为上述生产 API，可通过构建进程环境变量 PLAZA_API_BASE 显式指定同路径的 HTTPS 测试环境；不自动读取旧 .env.local，不包含密钥。esbuild 仅为开发工具，无第三方 JavaScript 运行依赖。

服务端源码、数据库升级及部署资料位于独立本地项目，不放入本仓库、不进入 EXE、不上传 GitHub；本仓库只保存客户端与必要接口约定。旧 CloudBase 代码与依赖已移除，不迁移其匿名身份或体验数据，也不自动删除旧远端资源。

隔离回归：tools/run_tests.py；node --test tests/test_plaza.js tests/test_rooms.js。Windows 联调必须覆盖取消发布、重复注入、页面重建、断线恢复和待撤下重试；无法在当前环境实测的场景应在交付说明中列明。

离开房间保留原生位置，发布/撤下按钮放在其左侧；显示/隐藏控制移到成员表头，不再占用房间信息区域。状态回包携带页面实例与序号，旧实例回包不投递到新页面，较旧的状态不覆盖新状态。

成员列表前提供「房间成员」表头，显示/隐藏他人桌宠改为表头右侧两个原生眼睛图标（显示与隐藏），支持悬停说明和键盘焦点；点击仍只调用原生在线成员的可见性按钮。表头沿用原生成员行的背景、圆角、高度、左右留白和文字样式，眼睛图标与成员行对齐。
